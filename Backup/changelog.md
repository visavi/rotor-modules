# Changelog

## Unreleased
- Если файл бэкапа не удалось создать (нет прав на каталог), бэкап останавливается сразу, а в журнале ошибок видно, какой файл не открылся; раньше падал посреди записи дампа с непонятной ошибкой типа
- Форма создания бэкапа проверяется правилами Laravel
- Строки в дампе экранируются средствами соединения с базой: значения с обратной косой чертой (пути Windows, JSON, регулярные выражения) раньше ломали восстановление дампа
- Способ сжатия, недоступный в PHP сервера, отклоняется ошибкой формы, а не падением страницы
- Таблица выгружается в одном снимке базы и по порядку первичного ключа: раньше порции без сортировки могли пересекаться, и на меняющейся таблице строки задваивались или терялись
- Имена колонок в дампе в обратных кавычках: колонка с именем вроде `key` или `order` ломала восстановление
- Список бэкапов — от новых к старым по времени файла: по имени с датой d-M-Y апрель стоял раньше января
- Удаление бэкапа спрашивает подтверждение
- Тесты: порядок списка, бэкап со сжатием gzip, удаление бэкапа

## 1.0.4
- Кнопки управления модулем в админке выводятся на языке пользователя, а не сайта: в `module.php` ключи перевода вместо `__()`, минимальная версия ядра — 14.7.0

## 1.0.3
- Импорты переведены с `App\Classes` на `App\Support`, минимальная версия ядра — 14.3.0

## 1.0.2
- Контроллеры переведены с устаревших `setFlash()`/`setInput()` на `redirect()->with()` и `->withInput()->withErrors()`: ошибки валидации отдаются редиректом (PRG), обновление страницы после ошибки не отправляет форму повторно
- Вьюхи переведены с устаревшего `getInput()` на стандартный `old()`

## 1.0.1
