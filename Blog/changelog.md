# Changelog

## Unreleased
- Удаление статьи берёт комментарии и их файлы двумя запросами, а не запросом на каждый комментарий; в режиме разработки удаление с несколькими комментариями падало с ошибкой 500
- Сортировка разделов в админке не падает с ошибкой 500 на массиве `order[]=`
- API списка статей и тегов, подсказки тегов не падают с ошибкой 500 на массиве `?tag[]=` и `?query[]=`
- Права на создание и правку статей — в `ArticlePolicy`: одно правило для сайта, API и шаблонов
- Кнопка «Добавить» скрыта, когда публикация статей закрыта, — раньше вела на отказ
- Отказ в правке чужой статьи показывает текст «Вы не автор данной статьи» — раньше выводился ключ перевода
- RSS блогов и список статей пользователя загружают файлы и разделы статей одним запросом, а не по запросу на статью
- Статьи на проверке и черновики пользователя видит только он сам — через ?active=0 их мог открыть любой вошедший
- Отказы (закрыто, не автор, нет записи и т.п.) отвечают кодом 403 или 404 вместо 200 с текстом ошибки — ajax и API видят ошибку по статусу
- Публикация статьи удалённого пользователя больше не начисляет награду всем пользователям сайта и не падает на отправке уведомления
- Публикация черновика при включённой модерации тоже ждёт проверки — раньше кнопка «опубликовать» делала статью активной сразу, на сайте и в API
- Закрытый приём статей сообщается до проверки полей формы; API отвечает 403 вместо 422
- Подсветка поля с ошибкой в настройках — под ядро 14.9: ключи ошибок `sets.имя` вместо `sets[имя]`
- Формы статьи на сайте, в админке и в API проверяются одними правилами Laravel, разделы в админке — тоже
- Поля формы статьи называются как в API: `category_id` и `published_at`; ссылка на создание с `?cid=` по-прежнему выбирает раздел
- Отложенная публикация без даты отклоняется — раньше статья сохранялась неактивной и не публиковалась никогда
- Антифлуд при создании статьи показывает ошибку под полем текста — раньше сообщение терялось
- Ошибка в имени раздела при правке подсвечивает поле — раньше уходила под чужой ключ
- API: длина текста считается без разметки, как на сайте; недоступный раздел — ошибка в поле `category_id`
- Разделы, сортировка и пересчёт закрыты на уровне маршрута (`check.admin:boss`); создание и правка статьи — `check.user`
- Требуется ядро 14.9.0
- Поле даты отложенной публикации не расходится с флажком после перезагрузки страницы: блок открывается средствами Bootstrap, без своего скрипта
- Подтверждение удаления и других необратимых действий — диалог сайта вместо системного окна браузера
- `Article::getFirstImage()` экранирует заголовок и путь

## 1.6.0
- Статьи и комментарии пользователя (`/articles/active/...`) — только авторизованным. Список авторов (`/blogs/authors`) тоже только авторизованным, гостю ссылки на него не показываются. В анкете гостю карточка без ссылок. В API `?user=` — только с токеном
- Облако тегов и подсказки тегов считают только опубликованные статьи: тег одних черновиков вёл на пустой список. Публикация и снятие статьи сбрасывают кэш облака
- Страница тега показывала и неопубликованные статьи
- API: `GET /api/tags` — облако тегов и подсказки по началу слова (`?query=`)
- API: в списке статей фильтры `?user=` (статьи пользователя) и `?tag=` (статьи с тегом), как на сайте
- Лента новых комментариев переехала на `/articles/comments`, как в других разделах; со старого `/articles/new/comments` — 301. Делится на страницы по первым 1000 комментариям, без подсчёта всех
- API: файлы, загруженные заранее, идут перед файлами из запроса — раньше вложения перемешивались
- Адрес подсказок тегов и лимит в 10 тегов задаются в форме статьи: ядро больше не знает про блоги
- Вложения в формах выводятся в порядке, заданном перетаскиванием миниатюр, а не по дате загрузки
- Требуется ядро 14.8.0

## 1.5.1
- Вызовы `antimat()` убраны: с ядра 14.7.0 фильтр слов применяется при выводе кастом модели, в базе хранится оригинал
- Заголовок статьи через `TextCast`: антимат действует и на него
- Название раздела (поиск, лента, жалобы) и кнопки управления в админке выводятся на языке пользователя, а не сайта: в `module.php` ключи перевода вместо `__()`
- Ссылки на блоги в анкете выводятся карточкой с иконкой и счётчиками статей и комментариев
- Страница настроек показывает боковую панель настроек сайта — переключение между разделами без возврата в админку
- Переключатели в настройках вместо галочек

## 1.5.0
- Миграция дат не падает при повторном запуске: временные колонки создаются только при отсутствии (`1060 Duplicate column name`)
- Таблицы создаются только при отсутствии — установка на базу со старого движка не падает (`1050 Table already exists`)
- Разделы блогов переставляются перетаскиванием прямо в списке админки, вместе с подразделами
- Список разделов в админке показывает вложенность любой глубины: раньше страница рисовала только два уровня
- Уровень раздела задаётся горизонтальным движением мыши, как в админках Drupal и XenForo
- Перетаскивание доступно только владельцу: админам ниже boss дерево показывается на чтение
- Счётчик раздела складывает статьи всей ветки, а не только свои
- Правка и удаление раздела — в одной строке списка и в одной строке формы правки
- Поле «Положение» убрано из формы правки раздела: порядок задаётся перетаскиванием
- Счётчик раздела на списке блогов складывает статьи всей ветки; вложенные разделы считались по другому правилу, чем корневые
- Последняя статья выводится одной строкой: название, автор и дата вместо двух строк с подписями
- Кнопка возврата из админки на сайт помечена глазом, а не ключом — как в остальных модулях
- Подразделы на списке блогов свёрнуты и раскрываются стрелкой, как на главной форума
- У счётчиков разделов появились подсказки «Статьи / Новые»
- Счётчик подраздела на странице раздела (и в админке) складывает всю ветку
