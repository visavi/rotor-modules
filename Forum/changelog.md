# Changelog

## 1.1.0
- Лимиты форм форума и голосований в `/api/config` объявляются модулем (секция `api` в `module.php`) — раньше они были захардкожены в ядре и приходили нулями без модуля
- Импорты переведены с `App\Classes` на `App\Support`, минимальная версия ядра — 14.3.0
- Счётчики тем и сообщений отдаются в `/api/stats` (ключи `topics` и `posts`)
- Методы API раздела описаны в своём `openapi.json` — документация на `/api` показывает их, только пока модуль включён
- Начисление баллов за сообщение переживает отсутствующую настройку модуля

## 1.0.9
- Чтение форума по API открыто гостю: `GET /api/forums`, `/api/forums/{id}` и `/api/topics/{id}` больше не требуют токен, как и сам сайт. С токеном ответ прежний, дополнительно приходит голос пользователя
- Создание темы и сообщения (`POST`) по-прежнему требуют токен

## 1.0.8
- Кураторы темы в админке: текстовое поле с логинами через запятую заменено на список с автодополнением (`bootstrap5-tags`, поиск через `/search-users`) — ввести несуществующий логин больше нельзя, максимум 10 кураторов
- `Admin/ForumController::editTopic`: проверка логинов кураторов делалась запросом на каждый логин с обрывом на первой ошибке — заменена одним `whereIn`, в ошибке перечисляются все ненайденные логины
- Исправлена ошибка валидации кураторов: писалась под ключ `moderator`, а вьюха читает `moderators` — сообщение о несуществующем логине не отображалось
- Формат хранения не изменился (CSV логинов в `topics.moderators`), миграция не требуется
- Требует ядро 14.2.2 (инициализация `.input-user` в `main.js`)

## 1.0.7
- Контроллеры переведены с устаревших `setFlash()`/`setInput()` на `redirect()->with()` и `->withInput()->withErrors()`: ошибки валидации отдаются редиректом (PRG), обновление страницы после ошибки не отправляет форму повторно
- Вьюхи переведены с устаревшего `getInput()` на стандартный `old()`
- `Admin/ForumController::actionTopic`: `switch` писал уведомление до общего редиректа — каждый `case` возвращает свой редирект
- `TopicController`: расчёт последней страницы темы дублировался в ветках успеха и ошибки, вынесен в `lastPage()`

## 1.0.6
- Исправлена запись тем в `feeds`: после перевода `feeds.created_at` на `DATETIME` (ядро 14.1.x) наблюдатель писал unix-таймстамп — MySQL сохранял `0000-00-00`, и темы пропадали из ленты (уходили в конец сортировки)
- Исправлен наблюдатель удаления поста: `topic.last_post_id` не обновлялся при удалении (контроллер этого не делает), из-за чего при удалении последнего поста в `feeds` писался NULL через пустой `withDefault()`; теперь последний пост пересчитывается в наблюдателе, обновляются и `last_post_id`, и дата в `feeds`

## 1.0.5
- Поля дат тем, сообщений и голосований (`posts`/`topics`/`votes`: `created_at`/`updated_at`) переведены с int (unix-таймстамп) на `DATETIME` (исторически-корректная конверсия таймзон, пересоздание составных индексов)
- Миграция разбита на 3 независимых файла (posts/topics/votes) — устойчивость к частичному сбою; конверсия батч-транзакциями (быстро на больших таблицах)
- Сравнения/арифметика дат переведены на Carbon/`now()`; включены авто-таймстампы вместо `$timestamps = false`: `Post` — полный авто (created_at + updated_at = время правки); `Topic`/`Vote` — `const UPDATED_AT = null` (created_at авто, `Topic.updated_at` остаётся ручным — время последнего поста и ключ сортировки активных тем; у `Vote` колонки updated_at нет). Свежий пост теперь имеет `updated_at = created_at` (раньше null), на «изменено» в UI не влияет (маркер = `edit_user_id`)
- Запись в `feeds` нормализована (`created_at->getTimestamp()`)
- ⚠️ На проде из-за размера `posts` миграцию запускать вручную через CLI (`php artisan migrate --path=modules/Forum/database/migrations`), не веб-кнопкой «Применить обновление» — иначе таймаут HTTP-запроса
- Требует ядро 14.1.0
