# Свои правки

Каталог `resources/custom` — место для правок владельца сайта. Файл, положенный сюда,
перебивает одноимённый файл ядра, темы или модуля, а оригинал остаётся нетронутым.

Обновление ядра этот каталог не трогает: он перечислен в `UpgradeService::$excluded`
рядом с `.env`, `modules` и `app/hooks.php`. Правки переживают и обновление модуля,
из которого взят шаблон или перевод.

## Структура

```
resources/custom/
├── views/                                  # шаблоны
│   ├── index.blade.php                     # перебивает resources/views/index.blade.php
│   ├── themes/default/footer.blade.php     # перебивает часть темы default
│   └── blog/index.blade.php                # перебивает шаблон модуля Blog
└── lang/                                   # переводы
    ├── ru/index.php                        # перебивает переводы ядра
    └── vendor/blog/ru/blog.php             # перебивает переводы модуля Blog
```

Каталог входит в поставку пустым, подкаталоги создавать не нужно.

## Шаблоны

Путь внутри `custom/views` повторяет путь оригинала:

| Что переопределяем | Оригинал | Файл в custom |
|---|---|---|
| Шаблон ядра | `resources/views/index.blade.php` | `custom/views/index.blade.php` |
| Часть темы | `resources/views/themes/default/footer.blade.php` | `custom/views/themes/default/footer.blade.php` |
| Шаблон модуля | `modules/Blog/resources/views/index.blade.php` | `custom/views/blog/index.blade.php` |

Для модуля берётся его ключ в snake_case — тот же, что в неймспейсе шаблонов
(`blog::index` → каталог `blog`).

Порядок поиска: **custom → тема → модуль (ядро)**. Тема по-прежнему может
переопределять шаблоны модулей через `themes/<тема>/views/<модуль>/`, а `custom`
стоит впереди неё.

Шаблон подменяется **целиком**: копируется весь файл и правится копия. Частичного
слияния у blade нет.

Переопределение части темы привязано к теме: файл в `custom/views/themes/default`
действует, только пока активна тема `default`.

### custom или тема

Тема тоже умеет переопределять шаблоны модулей — через `themes/<тема>/views/<модуль>/`
(см. «[Шаблоны](/docs/rotor-templates)»). Механизм тот же, отличается назначение:

|  | Тема | custom |
|---|---|---|
| Сколько | несколько, переключаются | одна на сайт |
| Когда действует | пока эта тема активна | всегда |
| Кто автор | автор темы | владелец сайта |
| Переносится ли | распространяется вместе с темой | остаётся на этом сайте |

Правка дизайна, которая едет вместе с темой, — в тему. Правка конкретного сайта,
которая не должна пропасть при смене темы, — в `custom`. При совпадении побеждает
`custom`.

При совпадении файла в теме и в `custom` берётся файл из `custom`.

## Переводы

В отличие от шаблонов, переводы **сливаются по ключам**. В файл кладутся только
изменённые строки, остальные берутся из оригинала:

```php
// resources/custom/lang/ru/index.php
<?php

return [
    'panel' => 'Управление',
];
```

Остальные ключи группы `index` продолжают приходить из `resources/lang/ru/index.php`.
Чтобы вернуть исходное значение, ключ достаточно удалить из файла.

Переводы модулей лежат в `custom/lang/vendor/<ключ модуля>/<локаль>/<группа>.php`:

```php
// resources/custom/lang/vendor/blog/ru/blog.php
<?php

return [
    'title' => 'Статьи',
];
```

Правки переводов удобнее делать через AdminPanel → Редактор файлов → Переводы:
там есть поиск по ключам и значениям, пометка изменённых строк и сброс к оригиналу.
Редактор пишет ровно в этот каталог.

В отличие от шаблонов, переводы не разделяются по темам — `custom/lang` действует всегда.

## Что сюда не входит

- **Исходники CSS и JS.** `resources/css` и `resources/js` собираются через Vite,
  правка без `npm run build` ничего не изменит. Свои стили и скрипты подключаются
  через `public/assets` (модуль StyleEditor) или через тему.
- **PHP-код ядра.** Контроллеры и модели переопределять нечем; для встраивания
  в логику используются хуки — см. раздел «Хуки».
- **Настройки.** Живут в базе, см. «Настройки сайта».

## Как это устроено

Три места в ядре:

```php
// config/view.php — шаблоны без неймспейса
'paths' => [
    resource_path('custom/views'),
    resource_path('views'),
],

// app/Http/Middleware/ApplySettings.php — шаблоны тем и модулей
// (для неймспейсов view.paths не используется)
$this->prependOverrides($finder, resource_path('custom/views'));

// app/Providers/AppServiceProvider.php — переводы ядра и модулей
$this->app['translation.loader']->addPath(resource_path('custom/lang'));
```

Каталога нет — накладных расходов тоже: проверка его наличия выполняется один раз
за запрос, и при отсутствии дальнейшая работа пропускается.
