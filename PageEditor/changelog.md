# Changelog

## 2.0.0
- Минимальная версия ядра — 14.6.0: каталог `resources/custom` появился в нём
- Редактор работает по нескольким корням (`views`, `lang`, `custom`, `modules`, `assets`), список задаётся в `config.php`. Исходники `resources/css` и `resources/js` намеренно не включены: они собираются через Vite, и правка из админки не дала бы эффекта без пересборки
- Имя файла указывается вместе с расширением, `.blade.php` перестал быть жёстко зашитым
- Проверка пути переведена на лексическую нормализацию: `realpath()` неприменим из-за символьных ссылок в `modules/*`
- Перед записью и удалением создаётся резервная копия в `storage/app/page-editor/backups`
- После записи `.php` вызывается `opcache_invalidate()`: на проде с `validate_timestamps=0` правки иначе не применялись
- Добавлены переименование и скачивание файлов
- Добавлен поиск по коду с маской имени, учётом регистра и режимом регулярных выражений
- Добавлен редактор переводов: поиск по ключам и значениям, правки пишутся в `resources/custom/lang` и переживают обновление ядра и модулей
- Маршрутам даны имена `admin.files.*`, редиректы переведены со строк на `route()`
- Работа с файловой системой убрана из шаблона списка в контроллер
- Исправлено удаление: при пустом имени файла и директории запрос сносил текущий каталог целиком, теперь требуется непустое имя
- Пути overlay и резервных копий вынесены в `config.php` (`overlay_path`, `backup_path`): тесты работают в собственном каталоге и больше не стирают боевые данные
- Редактор переводов: пустое значение по ключу, которого нет в исходниках, больше не пишется в overlay — иначе ломался фолбэк на `fallback_locale`
- Редактор переводов: переопределённые значения помечаются, у каждого есть чекбокс сброса — ключ удаляется из overlay и возвращается исходный перевод
- Скачивание: имя вложения берётся без каталогов, путь со слэшем больше не даёт 500
- Листинг считает строки только у редактируемых файлов — корень `assets` больше не читается в память целиком
- Листинг не считает строки и у крупных файлов: порог общий с редактором (`max_edit_size`)
- Битый overlay-файл, не возвращающий массив, больше не роняет страницу переводов
- Очистка поля у ключа, который есть в исходниках, записывает пустую строку осознанно: вернуть исходный перевод нужно чекбоксом сброса
- Хлебные крошки в листинге содержат постоянный пункт модуля, активный пункт показывает последний сегмент пути
- Корни переключаются вкладками, строка поиска доступна прямо в листинге
- Вкладки вынесены в общий шаблон и есть на странице переводов — из неё можно вернуться к файлам
- Корень, каталога которого ещё нет (`custom` до первой правки), открывается пустым списком вместо 404
- Каталог корня создаётся по требованию при создании в нём первого файла
- Строки переводов читаются с диска, а не через загрузчик: группы модулей больше не пустуют
- Выключенные модули помечаются значком — и в листинге `modules`, и в списке групп переводов
- Правки шаблонов и переводов собраны в `resources/custom` (`views` и `lang`): каталог перебивает тему, модули и ядро и не перезаписывается обновлением
- Вкладка корня `lang` названа «Языки», чтобы не совпадать с кнопкой редактора переводов
- Поиск: расширенные параметры (маска, регистр, регулярное выражение) убраны под «Дополнительно», маска подписана
- Поиск: найденный фрагмент подсвечивает вхождение
- Редактор переводов: поля стали многострочными, высота зависит от длины значения
- Редактор файлов: кнопка названа «Сохранить», подсказка про Ctrl+Enter заменена на верную (Tab добавляет отступ)
- Сохранение больше не съедает перевод строки в конце файла и отступ в начале: поле редактора исключено из обрезки пробелов
- Переводы строк из браузера приводятся к LF, файл всегда заканчивается одним переводом строки
- Видно, какой слой открыт: над редактором ссылка на парный файл — «Копия файла: …» из оригинала и «Оригинал файла: …» из копии, с путём парного файла
- В списке файлов у оригинала с правкой стоит значок
- В редакторе появилась кнопка «Сохранить в «Мои правки»»: копия уходит в custom, оригинал не меняется
- Счётчик объектов в каталоге считает так же, как листинг, — без скрытых файлов
- При правке файла модуля предупреждение: правка пропадёт при обновлении; для шаблонов и переводов подсказка сохранить в «Мои правки»
- Включённые модули помечены зелёным значком, выключенные — серым: и в листинге модулей, и в списке групп переводов
- «Где используется» ищет полный ключ (`группа.ключ`, у модулей `модуль::группа.ключ`) и без маски — раньше запрос уходил без имени группы и не находил ничего
- Поиск работает и по корню `Модули`: обход идёт по символьным ссылкам, петли отсекаются по реальному пути
- Добавлен раздел поиска «Код ядра» (`app`): ключи и хуки, используемые в контроллерах, теперь находятся. Файл открывается на просмотр с подсветкой строки, но поле недоступно для правки, а запись, удаление и листинг закрыты
- Если ничего не найдено, предлагаются остальные разделы поиска
- Таблица результатов поиска переводов больше не уезжает за экран
- Подсветка синтаксиса в редакторе: CodeJar и Prism (php, blade, css, js, разметка), два файла в `resources/assets/editor`, без сборки. Цвета подобраны и для тёмной темы. Без JS или для незнакомых расширений остаётся обычная textarea
- Панель над редактором: отменить, повторить и поиск по открытому файлу (Enter — вперёд, Shift+Enter — назад, счётчик совпадений). Доступные кнопки выделены цветом. В режиме просмотра доступен только поиск
- Подпись «Текст:» над полем убрана
- Группы переводов отсортированы: ядро сверху, модули снизу
- Вкладки корней переведены, у страницы переводов исправлена подпись кнопки поиска
- Файлы больше `max_edit_size` (1 МБ) не открываются в редакторе, вместо OOM — сообщение
- Переименование проверяет доступность каталога на запись, как создание и удаление
- Нормализация пути вырезает нулевые байты: `?path=a%00b` больше не даёт 500
- Листинг: корни переключаются вкладками вместо селектора с inline-`onchange`, поиск вынесен полем прямо в листинг, в хлебные крошки вернулся пункт «Редактор файлов»
